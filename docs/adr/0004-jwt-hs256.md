# ADR 0004: Self-issued JWT signed with a shared HS256 secret

**Status:** accepted for the reference project, to be replaced for production

## Context
We need stateless authentication that the gateway and every service can verify without calling auth-service per request.

## Decision
auth-service issues short-lived (1 h) JWTs signed with HS256. The secret comes from `JWT_SECRET` and is shared by
the gateway and the services, which validate it as OAuth2 resource servers.

## Consequences
- Simple to run locally with no key infrastructure.
- Every verifier could also forge tokens because it knows the signing secret. For production use asymmetric keys
  (RS256/ES256, verifiers only get the public key via JWKS) or an identity provider such as Keycloak, and add refresh
  tokens and token revocation.
- No roles beyond `USER` are enforced yet; the `roles` claim is already issued.
